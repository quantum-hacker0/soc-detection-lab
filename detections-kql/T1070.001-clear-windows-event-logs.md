# T1070.001 - Clear Windows Event Logs (Sentinel / KQL)

Windows analog of the Linux log-clearing rule (T1070.003). Clearing the Security log emits
a single high-fidelity event (1102) - one of the cleanest detections there is.

| Field | Value |
|---|---|
| ATT&CK | T1070.001 - Indicator Removal: Clear Windows Event Logs |
| Platform | Microsoft Sentinel (SecurityEvent) |
| Sample | EVTX-ATTACK-SAMPLES: `Defense Evasion/DE_1102_security_log_cleared.evtx` |

## KQL
```kql
SecurityEvent
| where EventID == 1102            // Security audit log was cleared
| project TimeGenerated, Computer, Account = SubjectUserName, SubjectDomainName
| union (
    Event
    | where EventLog == "System" and EventID == 104   // other log cleared
    | project TimeGenerated, Computer, RenderedDescription
)
```

## Validation
- Against the sample: 1 event with EventID 1102 (Security log cleared). Fires immediately.
- Unlike the Linux `history -c` blind spot, Windows log-clearing is logged natively, so this
  rule has no equivalent gap - a good contrast to note.

## Notes
- Near-zero false positives: legitimate log clears are rare and usually tied to a known
  maintenance change. Alert high-severity.
- An attacker who stops the EventLog service or tampers at the ETW level instead of clearing
  leaves a different footprint (service-stop / ETW events) - out of scope for this rule.
