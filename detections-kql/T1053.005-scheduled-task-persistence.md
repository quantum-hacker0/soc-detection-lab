# T1053.005 - Scheduled Task Persistence (Sentinel / KQL)

Windows analog of the Linux cron rule (T1053.003). Same tactic (persistence via a
scheduler); on Windows a created task raises Security EventID 4698.

| Field | Value |
|---|---|
| ATT&CK | T1053.005 - Scheduled Task/Job: Scheduled Task |
| Platform | Microsoft Sentinel (SecurityEvent 4698) / Defender XDR (DeviceProcessEvents) |
| Sample | EVTX-ATTACK-SAMPLES: `Privilege Escalation/PrivEsc_SeImpersonatePriv_enabled_back_for_upnp_localsvc_4698.evtx` |

## KQL - Sentinel (task created, 4698)
```kql
SecurityEvent
| where EventID == 4698                       // A scheduled task was created
| extend Task = tostring(TaskName)
| where SubjectUserName !endswith "$"          // exclude machine-account/system installers if desired
| project TimeGenerated, Computer, Account = SubjectUserName, Task, TaskContent
```

## KQL - Defender XDR (schtasks.exe / at.exe execution)
```kql
DeviceProcessEvents
| where FileName in~ ("schtasks.exe", "at.exe")
| where ProcessCommandLine has_any ("/create", "/ru system", "/sc onlogon", "/sc onstart")
| project Timestamp, DeviceName, AccountName, InitiatingProcessFileName, ProcessCommandLine
```

## Validation
- Against the sample: 1 event with EventID 4698, `TaskName` = `\FullPowersTask`,
  created under `LOCAL SERVICE` - a task created as part of a privilege-escalation chain.
- The `TaskContent` field carries the task XML (action, trigger), which the analyst pivots
  into during triage.

## Notes
- Legitimate software and admins create scheduled tasks; tuning is on the task name, the
  action path, and the creating account (same shape as excluding apt/dpkg on the cron rule).
- Pair 4698 (created) with 4702 (updated) for tasks that are modified rather than created.
