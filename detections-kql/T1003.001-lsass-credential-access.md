# T1003.001 - LSASS Credential Access (Sentinel / KQL)

Windows analog of the Linux `/etc/shadow` rule (T1003.008). Same idea: a process that
isn't a known security component reads credential material - here, opening a handle to
`lsass.exe` with process-access rights.

| Field | Value |
|---|---|
| ATT&CK | T1003.001 - OS Credential Dumping: LSASS Memory |
| Platform | Microsoft Sentinel (SecurityEvent) / Defender XDR (DeviceEvents) |
| Sample | EVTX-ATTACK-SAMPLES: `Credential Access/CA_hashdump_4663_4656_lsass_access.evtx` |

## KQL - Sentinel (Windows Security log, 4656/4663)
```kql
SecurityEvent
| where EventID in (4656, 4663)
| where ObjectName endswith "lsass.exe"
| where AccessMask in ("0x1010", "0x1410", "0x1438", "0x143a", "0x1f3fff")   // read/VM_READ rights
| where ProcessName !endswith "\\wininit.exe"
    and ProcessName !endswith "\\MsMpEng.exe"        // Defender
    and ProcessName !endswith "\\lsass.exe"
| project TimeGenerated, Computer, Account, ProcessName, ObjectName, AccessMask
```

## KQL - Defender XDR advanced hunting (equivalent)
```kql
DeviceEvents
| where ActionType == "OpenProcessApiCall"
| where FileName =~ "lsass.exe"
| where InitiatingProcessFileName !in~ ("wininit.exe","MsMpEng.exe","csrss.exe")
| project Timestamp, DeviceName, InitiatingProcessFileName, InitiatingProcessCommandLine
```

## Validation
- Against the sample: 2 matching events (4656 + 4663), `ObjectName` =
  `...\Windows\System32\lsass.exe`, `AccessMask` = `0x1f3fff`, `ProcessName` =
  `C:\Windows\System32\cscript.exe` (a scripting host reading LSASS - not a security tool).
- The exclusion list keeps signed security components from firing (same tuning approach as
  the Linux rule, which excluded `unix_chkpwd`).

## Notes
- Written against the standard Sentinel/Defender schemas and validated against the sample
  event's real fields. Not executed in a live tenant (no Azure subscription in the lab).
- `0x1f3fff` is full access; the narrower masks catch tools that request only VM_READ.
