# T1059.001 - Obfuscated PowerShell (Sentinel / KQL)

Windows analog of the Linux suspicious-shell rule (T1059.004). There it was `base64 -d`
and `/dev/tcp`; here it's obfuscated PowerShell in script-block logs (EventID 4104).

| Field | Value |
|---|---|
| ATT&CK | T1059.001 - Command and Scripting Interpreter: PowerShell |
| Platform | Microsoft Sentinel (PowerShell Operational 4104) |
| Sample | EVTX-ATTACK-SAMPLES: `Credential Access/phish_windows_credentials_powershell_scriptblockLog_4104.evtx` |

## KQL
```kql
Event
| where Source == "Microsoft-Windows-PowerShell" and EventID == 4104
| extend Script = tostring(EventData.ScriptBlockText)
| where Script has_any (
    "[scriptblock]::create", "IEX", "Invoke-Expression",
    "FromBase64String", "New-Object System.IO.StreamReader",
    "-enc", "-EncodedCommand", "DownloadString", "DownloadFile",
    "System.Net.WebClient", "Reflection.Assembly")
| project TimeGenerated, Computer, ScriptSnippet = substring(Script, 0, 300)
```

## Validation
- Against the sample: 2 events with EventID 4104. `ScriptBlockText` begins
  `&([scriptblock]::create((New-Object System.IO.StreamReader(New-Obj...` - reflective
  script-block construction over a stream, a common obfuscation/loader pattern. Matches on
  both `[scriptblock]::create` and `New-Object System.IO.StreamReader`.

## Notes
- Requires PowerShell Script Block Logging enabled (GPO / registry) - the Windows analog of
  making sure your Linux sensor actually watches the thing you want to detect.
- Admin automation legitimately uses some of these cmdlets; tune per-environment by the
  calling context, and weight multiple indicators in one script higher.
