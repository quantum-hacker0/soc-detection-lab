# T1021.004 - SSH Lateral Movement

| Field | Value |
|---|---|
| ATT&CK | T1021.004 - Remote Services: SSH |
| Tactic | Lateral Movement |
| Data source | Sysmon EID 1 (ProcessCreate); EID 3 (network) for the destination |
| Severity | Medium |
| Status | validated |

## Hypothesis
After initial access, attackers pivot to other hosts over SSH. On a server that is normally
an SSH *destination* (people ssh IN), the ssh *client* running outbound - especially with
`StrictHostKeyChecking=no` to suppress unknown-host prompts - is anomalous. The baseline
ran no outbound ssh, confirming it is not part of normal activity here.

## Detection (SPL)
```
index=soclab sourcetype=linux:sysmon
| rex field=_raw "<EventID>(?<eid>\d+)"
| rex field=_raw "<Data Name=\"Image\">(?<img>[^<]+)"
| rex field=_raw "<Data Name=\"CommandLine\">(?<cmd>[^<]+)"
| rex field=_raw "<Data Name=\"User\">(?<user>[^<]+)"
| where eid=1 AND match(img,"/ssh$")
| eval suspicious=if(match(cmd,"StrictHostKeyChecking=no"),"YES","")
| table _time user suspicious cmd
```

## Known limitations
- On a host where admins routinely ssh outbound, the base rule is noisy - there the value
  is in the `StrictHostKeyChecking=no` flag and in correlating with the EID 3 destination
  (alert on connections to NEW/internal hosts the box never talks to).
- Pivoting via an existing SSH `ControlMaster` socket reuses a connection and spawns no new
  ssh client - would need network-side (EID 3) detection instead.
- SCP/SFTP/rsync-over-ssh are separate images - add them to the `match()` for full coverage.
