# T1053.003 - Cron Job Persistence

| Field | Value |
|---|---|
| ATT&CK | T1053.003 - Scheduled Task/Job: Cron |
| Tactic | Persistence |
| Data source | Sysmon EID 11 (FileCreate); auditd (corroborating) |
| Severity | High |
| Status | validated |

## Hypothesis
Attackers gain persistence by writing a job into cron. On a server, files under
`/etc/cron.d/`, `/etc/cron.*/`, and `/var/spool/cron/` change rarely and only via a small
set of admin tools (package installers, config management). A file *created* there outside
those channels is a strong persistence signal.

## Detection (SPL)
```
index=soclab sourcetype=linux:sysmon
| rex field=_raw "<EventID>(?<eid>\d+)"
| rex field=_raw "<Data Name=\"TargetFilename\">(?<file>[^<]+)"
| rex field=_raw "<Data Name=\"Image\">(?<who_ran>[^<]+)"
| where eid=11 AND (like(file,"/etc/cron%") OR like(file,"/var/spool/cron%"))
| table _time who_ran file
```

## Known limitations
- A user crontab written via `crontab -e` lands in `/var/spool/cron/crontabs/` - covered by
  the second path. But `crontab` editing via its own tmpfile may need the auditd view.
- An attacker who MODIFIES an existing cron file rather than creating one may not raise a
  FileCreate (EID 11). Add EID 23 (FileDelete) / a file-integrity check for full coverage.
