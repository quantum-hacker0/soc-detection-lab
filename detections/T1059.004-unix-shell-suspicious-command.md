# T1059.004 - Suspicious Unix Shell Command

| Field | Value |
|---|---|
| ATT&CK | T1059.004 - Command and Scripting Interpreter: Unix Shell |
| Tactic | Execution |
| Data source | Sysmon EID 1 (ProcessCreate) |
| Severity | Medium-High |
| Status | validated |

## Hypothesis
Two shell patterns are near-universal in attacks and near-absent in legitimate admin work:
(1) `base64 -d` piped into a shell (payload obfuscation), and (2) a `/dev/tcp/HOST/PORT`
redirect (bash's built-in reverse-shell/exfil primitive). Either in a command line is a
strong execution signal.

## Detection (SPL)
```
index=soclab sourcetype=linux:sysmon
| rex field=_raw "<EventID>(?<eid>\d+)"
| rex field=_raw "<Data Name=\"CommandLine\">(?<cmd>[^<]+)"
| where eid=1 AND (match(cmd,"base64\s+-d") OR match(cmd,"/dev/tcp/"))
| table _time cmd
```

## Known limitations
- Base64 has legitimate uses (encoding a file, not decoding-to-shell); this rule keys on
  `-d` (decode). A CI/CD or deploy script that base64-decodes config could FP - exclude by
  parent process in production.
- Attackers can obfuscate differently (xxd, uudecode, hex, gzip). This rule covers the two
  most common; broaden the `match()` alternation as you see new tradecraft.
- `/dev/tcp` is bash-specific; a python/perl reverse shell needs a separate pattern
  (`socket`, `pty.spawn`) - candidate for a follow-up rule.
