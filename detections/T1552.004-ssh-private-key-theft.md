# T1552.004 - SSH Private Key Theft

| Field | Value |
|---|---|
| ATT&CK | T1552.004 - Unsecured Credentials: Private Keys |
| Tactic | Credential Access |
| Data source | Sysmon EID 11 (FileCreate) |
| Severity | High |
| Status | validated |

## Hypothesis
SSH key material (`id_rsa`, `id_ed25519`, `authorized_keys`, `known_hosts`) legitimately
lives under a `.ssh/` directory. When a file with one of those names is *created* somewhere
else - `/tmp`, a staging/loot dir, an archive path - it is being copied out for theft or
exfil. The invariant is the filename appearing OUTSIDE `.ssh`, not any specific tool.

## Detection (SPL)
```
index=soclab sourcetype=linux:sysmon
| rex field=_raw "<EventID>(?<eid>\d+)"
| rex field=_raw "<Data Name=\"TargetFilename\">(?<file>[^<]+)"
| rex field=_raw "<Data Name=\"Image\">(?<who_ran>[^<]+)"
| where eid=11 AND match(file,"(id_rsa|id_ed25519|id_ecdsa|authorized_keys|known_hosts)$") AND NOT match(file,"/\.ssh/")
| table _time who_ran file
```

## Known limitations
- An attacker who renames keys during theft (`cp id_rsa /tmp/x`) evades the filename match.
  A stronger version also flags any process READING multiple files under `.ssh/` in quick
  succession (requires read auditing via auditd `-w ~/.ssh -p r`).
- Reading a key into memory and exfiltrating over the network without touching disk would
  not raise EID 11 - pair with the Sysmon EID 3 network view for the exfil leg.
