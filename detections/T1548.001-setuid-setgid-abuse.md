# T1548.001 - Setuid/Setgid Abuse

| Field | Value |
|---|---|
| ATT&CK | T1548.001 - Abuse Elevation Control: Setuid and Setgid |
| Tactic | Privilege Escalation |
| Data source | Sysmon EID 1 (ProcessCreate); auditd (chmod syscall) |
| Severity | High |
| Status | validated |

## Hypothesis
Creating a setuid-root binary (`chmod 4755`, `u+s`) is a common persistence/privesc move:
drop a root-owned setuid shell, come back to it later for instant root. The setuid bit in a
chmod command is the signal; it is rare in normal admin work.

## Detection (SPL)
```
index=soclab sourcetype=linux:sysmon
| rex field=_raw "<EventID>(?<eid>\d+)"
| rex field=_raw "<Data Name=\"CommandLine\">(?<cmd>[^<]+)"
| where eid=1 AND match(cmd,"chmod\s+([0-7]*)?[46][0-7][0-7][0-7]")
| table _time cmd
```
(The `[46]` leading octal digit = setuid (4) or setgid+setuid (6) bit set.)

## Validation
- [x] Fires on: T1548.001 (`chmod 4755 /tmp/rootbash`) and T1068's `chmod 4755 /tmp/rooted` - 3 rows
- [x] Silent on: `index=soclab_baseline` - 0 rows
- [x] FP count on baseline after tuning: 0

## Known limitations
- `chmod u+s` (symbolic) evades the octal regex - add a `u\+s` alternation.
- Setting the bit via a C program's `chmod()` syscall (not the chmod binary) needs the
  auditd syscall view (`syscall=90 mode` with setuid bit) instead of the command line.
- Catches creation, not USE - a setuid binary that already exists and is executed is
  covered by the T1068 uid-transition rule.
